# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Go SDK for [Jamf Protect](https://www.jamf.com/products/jamf-protect/). Extracted from [terraform-provider-jamfprotect](https://github.com/Jamf-Concepts/terraform-provider-jamfprotect) to enable reuse across tools (Terraform provider, CLI tools, other integrations).

The module path is `github.com/Jamf-Concepts/jamfprotect-go-sdk`.

## Architecture

The SDK has two layers:

- **`jamfprotect` (exported)** — Public API. Provides a `Client` with typed methods for each Jamf Protect resource. Consumers import only this package.
- **`internal/client`** — GraphQL transport, OAuth2 token management, pagination, error handling. Not importable by external consumers.

The transport client handles:
- OAuth2 client credentials flow against `POST {base_url}/token` (sends `client_id` + `password`, receives `access_token` without Bearer prefix)
- Thread-safe token caching with `sync.Mutex` + `singleflight.Group`
- Retryable HTTP with exponential backoff (3 retries, 1-30s)
- Two GraphQL endpoints: `/graphql` (limited, introspection enabled) and `/app` (full API, introspection disabled — SDK uses `/app`)

## Code Generation

**Every file in `jamfprotect/` except `client.go` is code-generated. Do not hand-edit them.**

The generator lives at `tools/generate/`. It reads `testing/schema.graphql` (full schema, gitignored) and `tools/generate/config.json` and emits Go source into `jamfprotect/`. It also emits a filtered schema slice to `schema/schema.graphql` (committed) covering only the types/fields referenced by config — CI regenerates from this filtered schema without needing the private full schema.

- **Generated files** — driven by `config.json` `resources` array. To change a generated file, update `config.json` and re-run `make generate`.
- **Static-emitted files** — driven by `config.json` `statics` array. Source lives in `tools/generate/_static/`. Edit there, then run `make generate` to copy to `jamfprotect/`. Current statics: `audit_log_helpers.go`, `doc.go`, `errors.go`, `rbac.go`, `types.go` — all marked KEEP-STATIC per `tools/generate/STATIC_AUDIT.md` (one-off helpers with no reasonable templating path).
- **`client.go`** — intentionally handwritten. Not touched by the generator.

All generated and static-emitted files carry `// Code generated by tools/generate. DO NOT EDIT.` as the third line.

### Generator layout

The generator is split across files by concern (all `package main`):

- `main.go` — CLI entry; reads config, walks resources, calls emit functions.
- `config.go` — `Config`, `ResourceConfig`, `OperationConfig`, `NestedTypeConfig`, etc. — every JSON-config struct lives here.
- `schema.go` — schema-side helpers: `resolveGoType`, `baseTypeName`, scalar/enum mapping, input tree flattening.
- `filter.go` / `filter_test.go` — schema slimming for CI commit.
- `validate.go` — config validation.
- `emit.go` — template rendering and static file copy.
- `templates/resource.go.tmpl` — single shared text/template for every generated file.
- `ir.go` — orchestrator: `buildIR` only, glues the IR pieces together.
- `ir_types.go` — IR struct definitions (`IRResource`, `IRStruct`, `IROperation`, `IRField`, `BuildVar`, …) and the `bt` backtick const.
- `ir_fragment.go` — `buildFragment`, `writeFragmentSubFields` (GraphQL fragment construction including inline-fragment unions).
- `ir_response.go` — `buildResponseTypes`, `buildNestedStruct`, `buildUnionMergedStruct`, pointer/path wrapping helpers.
- `ir_input.go` — `buildInputTypesAndHelpers`, `buildNestedInputTypes`, `buildMultiWrappedInputTypes`, `buildVarsFuncBody`, type-rename helpers.
- `ir_op.go` — operation dispatcher: `buildOperations`, `buildOperation`, `inlineArgsSignature`.
- `ir_op_query.go` — per-kind GQL query-string builders (`buildCreateStr`, `buildUpdateStr`, `buildPaginatedListStr`, `buildListItemsStr`, `buildInlineArgsMutationStr`, `buildMultiWrappedMutationStr`, nested input-literal tree, etc.) + `buildQueryStr` kind switch.
- `ir_op_body.go` — per-kind Go method-body builders (`buildGetBody`, `buildCreateBody`, `buildSingletonGetBody`, `buildListItemsBody`, `buildMultiWrappedUpdateBody`, …) + `buildMethodParts` kind switch.
- `ir_helpers.go` — low-level utilities: `formatGoLiteral` (recursive Go literal emission for `map[string]any` / `[]any`), `buildMapLit`, `mergeVarsExpr`, `primitiveZeroExpr`, `zeroVal`, `inlineArgZeroCheck`, `sortedStringKeys`.

When adding a new generator feature: most config additions land in `config.go` + one of the `ir_op_*` files; new response/input shapes land in `ir_response.go` / `ir_input.go`; new GQL selection patterns land in `ir_fragment.go`. The IR-shape changes go in `ir_types.go` and the orchestrator hookup in `ir.go`.

### Operation kinds

`OperationConfig.kind` switches dispatch in both query and body builders. Current kinds:

- `get`, `create`, `update`, `delete` — standard CRUD shapes.
- `list` — paginated list with `client.ListAll` cursor loop (default for `List*` methods).
- `list_simple` — non-paginated `[T]` top-level return (no items/pageInfo wrapper).
- `list_items` — non-paginated `{items: [T]}` shape with inline-literal input args; auto-derives the inner GQL selection from an `ExtraResponseType` matching `returnType` when no `inlineFields` are configured.
- `singleton_get` — zero-arg get; supports `resultPath` for nested-result extraction, `resultPathLeaf` for scalar-leaf selection, `noSelection` for scalar field calls, `gqlVars` for hidden GQL var declarations whose values come from `extraVarValues`.
- `singleton_update`, `update_inline` — primitive-arg mutations wrapped in `input: {…}`.
- `mutation_list` — mutation returning `{items: [T]}`.
- `multi_wrapped_update` — mutation taking multiple typed input variables (e.g. DataForwarding's `$s3`, `$sentinel`, `$sentinelV2`).
- `date_paginated` — date-range cursor pagination (audit logs).

## Dependencies Policy

Only use native Go and `golang.org/x` packages. Do not introduce third-party dependencies without discussion. Current transport dependencies: `hashicorp/go-retryablehttp`, `golang.org/x/sync`.

## Code Style

- Every exported constant, function, variable set, and type must have a short comment describing its purpose.
- Do not add comments inside type definitions or function bodies.
- Wrap errors with `fmt.Errorf("context: %w", err)` to preserve error chains.
- Sentinel errors: `ErrAuthentication`, `ErrGraphQL`, `ErrNotFound` (defined in internal/client).

## Service Method Conventions

Each resource has typed CRUD methods on the client following this pattern:

```go
func (c *Client) CreateRole(ctx context.Context, input RoleInput) (Role, error)
func (c *Client) GetRole(ctx context.Context, id string) (*Role, error)
func (c *Client) UpdateRole(ctx context.Context, id string, input RoleInput) (Role, error)
func (c *Client) DeleteRole(ctx context.Context, id string) error
func (c *Client) ListRoles(ctx context.Context) ([]Role, error)
```

Each resource file contains GraphQL queries/mutations as constants, Go types for request/response payloads, and the CRUD method implementations. GraphQL fragments are appended to query constants for field reuse. These files are code-generated — modify `tools/generate/config.json` or `tools/generate/_static/` instead of editing them directly.

**Read + Write (partial):** Computer (list, get, update, delete, setComputerPlan), Connection (list-only), DataForwarding (get/update), DataRetention (get/update), ChangeManagement (get/update), Downloads (get-only)

**Alerts:** GetAlert, ListAlerts, UpdateAlerts (bulk status), GetAlertStatusCounts

**Insights/Compliance:** ListInsights, UpdateInsightStatus, ListInsightComputers, GetFleetComplianceScore

**Audit Logs:** ListAuditLogsByDate (2-day max sliding window), ListAuditLogsByUser, ListAuditLogsByOp

**Auth:** GetCurrentPermissions (RBAC introspection)

**Dashboard:** GetCount (aggregated computer/alert/insight counts), GetComputerCount, ListRiskiestComputers (limit, createdInterval). `GetCount` must pass `{or: []}` match-all filters per `CountQueryInput` field — `{}` or `null` make the server return null counts.

## RBAC Variables

Some GraphQL queries require RBAC permission-scoping variables (e.g., `RBAC_Connection`, `RBAC_Role`, `RBAC_Plan`). These are merged into query variables using `mergeVars()`.

## Environment Variables

- `JAMFPROTECT_URL` — Base URL (e.g., `https://your-tenant.protect.jamfcloud.com`)
- `JAMFPROTECT_CLIENT_ID` — API client ID
- `JAMFPROTECT_CLIENT_SECRET` — API client secret

Acceptance tests use `JAMFPROTECT_BASE_URL` (not `JAMFPROTECT_URL`) plus `JAMFPROTECT_CLIENT_ID` and `JAMFPROTECT_CLIENT_SECRET`.

## Schema

`testing/` and `bin/` are gitignored — the full private schema is not committed. To run the generator locally with full-schema access, obtain `schema.graphql` from the private API repo and place it at `testing/schema.graphql`. The audit of SDK coverage is at `bin/AUDIT.md` (committed via `git add -f`).

`schema/schema.graphql` IS committed — it is the filtered slice covering only types referenced by `config.json`, emitted by the generator's filter pass (`tools/generate/filter.go`). CI regenerates from this filtered schema alone. Simulate the CI case locally with `mv testing testing.tmp && make generate && mv testing.tmp testing` — output must be byte-identical to the full-schema run.
